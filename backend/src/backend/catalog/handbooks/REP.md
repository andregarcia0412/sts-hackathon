# Handbook — Transferência/reprodução (REP)

O conhecimento novo deve poder ser transferido e os resultados reproduzidos por outros, inclusive os negativos
(Frascati 2015 §2.20). É este critério que separa "Elegível" de "Com ressalvas".

## Armadilhas

- **REP-D7**: um limite excluído desde o início não gera ressalva. Uma lacuna DENTRO da pretensão original (hipótese
  do protocolo não ensaiada, flag `..._executado: false`, critério prévio não atingido) gera ressalva técnica: recorte
  sustentado, limitação concreta e evidência necessária. A ressalva é técnica, não "falta reprodução por outra
  equipe".
- **REP-D8**: documentação completa de uma configuração reproduz a configuração de um produto, não um conhecimento
  novo.
- **REP-D9/REP-D2**: só o recálculo a partir das medições valida os números; o mesmo número repetido num PDF não é
  confirmação independente.
- **REP-D3**: resultado negativo documentado conta a favor (falha experimental registrada é conhecimento).
- **REP-D4**: o pacote não traz código executável; o artefato é especificação, configuração e registros por versão.

## Quando usar cada estado

- **DOCUMENTADA NO ESCOPO** (P&D): método, configuração e resultados recalculáveis para o núcleo alegado, sem lacuna
  dentro da pretensão.
- **DOCUMENTADA COM LIMITE** (P&D com ressalva): igual, mas uma hipótese ou cenário da própria pretensão ficou sem
  ensaio ou um critério prévio não foi atingido. Preencha recorte, limitação e evidência necessária.
- **DOCUMENTADA PARA A CONFIGURAÇÃO** (rotina): a documentação permite reproduzir a configuração de um produto.
- **INSUFICIENTE PARA O NÚCLEO ALEGADO** (insuficiente): use SOMENTE quando os resultados do núcleo não são
  recalculáveis do registro primário (sem medições, só memorando). Documentação completa nunca é insuficiente.

## Sinais que não contam

Repetição de número em dossiê ou registro técnico; "próxima ação" registrada (todos os projetos têm); depoimento da
entrevista; `natureza_informada_pela_equipe`.
